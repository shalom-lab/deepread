# 多选条目整理能力开发

> 本地审阅用需求稿（截至 v0.11.6 讨论结论）。  
> 实现旁路细节见 `docs/multi-item-organize-agent.md`。

---

## 1. 目标任务

做出与「单篇 AI 阅读」**产品分立**的 **DeepRead 条目整理**：用户多选文献后，用写死指令生成可核对方案，**人工 OK 后才改库**。

### 首期必须交付

| # | 交付物 | 验收标准 |
|---|--------|----------|
| 1 | 独立整理入口 | 多选时用户能**稳定打开**整理 UI（有可见窗口/面板，不是静默无反应） |
| 2 | 指令 `organize_rename` | 官方标题建议 + 附件角色命名提案 |
| 3 | 人工拍板 | 展示 from→to、来源、把握度；勾选后才写库；OK 前零写库 |
| 4 | 安全范围 | 只允许操作**本次选中**的顶层条目 / PDF·Word 附件 ID；越权拒绝 |
| 5 | 高风险默认关 | `delete_attachment` / `move_attachment` 原子已具备，UI 默认不勾选、首期可不暴露 |

### 明确非目标（首期不做）

- 不把整理塞进阅读侧栏聊天 / 不共用阅读历史与预设。
- 不指望多选时仍显示 Item Pane 自定义 section 图标（Zotero 核心限制）。
- 不静默自动改名、不无人值守批跑。
- 首期不做完整「删附件 / 挪附件」混合方案表 UI。

---

## 2. 背景信息

### 用户场景

多选一批「标题乱 / 附件名乱」的条目，希望：

1. **条目标题** → 仅来自 PubMed / Crossref（或已有 DOI·PMID 可解析的官方元数据），禁止模型瞎编标题。  
2. **附件文件名** → `角色_第一作者 et al_年_期刊_title`（过长截断 title）；角色含 Manuscript / Preprint / Accepted / Proof / AppendixN。  
3. 预览附件内容时 **最多前 5 页**（不足则全文）；笔记 / HTML 不进改名白名单。  
4. 先看 log + 把握度，再点 OK。

### 与 AI 阅读的关系

| | AI 阅读（现有） | 条目整理（本需求） |
|--|----------------|-------------------|
| 场景 | 单篇精读 | 多选批处理 |
| 入口 | 单选 → Item Pane section | **独立入口**（菜单 / 对话框） |
| 交互 | 自由对话 + 用户预设 | 写死指令 + 确认表 |
| 改库 | 基本不改条目本体 | 确认后改标题/附件名 |
| 配置 | 共用 Provider / API Key / 模型 | 同左 |

### Zotero 平台约束（必须写进方案）

| 事实 | 对产品的含义 |
|------|----------------|
| `registerSection` 只服务**单个** `item` | 阅读侧栏只能单选用 |
| 多选时核心会藏掉**所有**自定义 Item Pane section（`extraItems` 时只留 Info；混合选中走 message） | **不能**靠侧栏图标做多选整理 |
| 主窗口是 XUL；往主窗口硬贴 HTML 浮层经常**看不见** | 整理 UI 必须用**独立对话框窗口**（如 `openDialog("about:blank")`）或等价可靠载体 |
| 官方无「多选自定义 section」API | 入口只能是：右键菜单、工具菜单、多选空白区旁路按钮、独立窗 |

### 模块与职责（现状/目标）

```
agents/OrganizeAgent.js     选中收集、提案编排、模型角色分类、apply
agents/OrganizeDialog.js    整理 UI（独立窗口）
tools/OfficialMetaLookup.js PubMed / Crossref
tools/OrganizeRenameTool.js 组合提案 → 原子步骤
tools/ZoteroAtomTools.js    原子写库 + scope 白名单 + runPlan
deepread.js                 菜单 /（可选）多选旁路入口安装
```

### 原子 Tool（执行层）

| id | 风险 | 首期 UI |
|----|------|---------|
| `set_item_title` | 中 | 可勾选执行 |
| `rename_attachment` | 中 | 可勾选执行 |
| `set_item_field` | 中 | 预留 |
| `delete_attachment` | 高 | 默认不勾；首期可不展示 |
| `move_attachment` | 高 | 默认不勾；首期可不展示 |

`runPlan(steps, scope)`：**无 scope 拒绝**；步骤 ID 不在白名单 → `rejected`。

### 命名规则（cite-stem）

- 附件：`{Role}_{Author}[ et al]_{Year}_{Journal}_{title}`  
- Role 首字母大写风格与现实现一致（Manuscript / Appendix1 …）  
- 文件系统安全字符；title 过长截断

## 3. 工作要求

### 产品与安全

1. **OK 前零写库**；所有写库走原子层 + scope。  
2. 标题必须带 `officialSource`（或等价官方来源字段）；无官方来源不得改标题。  
3. scope 仅含本次选中顶层条目 + 其子 PDF/Word；笔记/HTML 排除。  
4. 高风险原子默认 `selected=false`。  
5. 模型 JSON 校验失败可重试（有上限），失败则回退规则分类并在 log 标明。

### 交互与入口

1. **主入口必须可见、可点、有反馈**：打开失败要用 alert / 明确错误，禁止静默。  
2. 必装入口至少两处：  
   - 文献列表右键：`DeepRead 条目整理…`  
   - 工具菜单：同名项  
3. 多选右侧「已选择 N 个条目」旁路入口可选；**不能替代**对话框可靠性。  
4. 整理 UI 使用**独立窗口**，不依赖 Item Pane section，不依赖往 XUL 主窗口贴 HTML overlay。

### 工程约定

1. 版本随功能点升版（manifest + package）；需要发布时打 tag。  
2. 整理相关脚本经 `bootstrap.js` 加载，经 `build.js` 打进 xpi。  
3. 不把整理会话写入 `deepread_history`。  
4. 中英文文案成对；默认跟 Zotero locale。

### 禁止

- 禁止用阅读侧栏冒充多选整理主界面。  
- 禁止模型发明官方标题。  
- 禁止在无人工确认时执行删/挪。  
- 禁止 `runPlan` 在无 scope 时写库。

## 4. 工作流程

### Step 1 — 对齐入口与窗口载体

确认整理只能走独立对话框（或经验证的等价方案）；菜单点击必有窗口或错误提示。

### Step 2 — 收集选中范围并建 scope

从 `ZoteroPane.getSelectedItems()` 归一到顶层 regular item；`buildScopeFromItems` 生成 item/attachment 白名单。

### Step 3 — 生成提案（不写库）

- 官方元数据查标题；  
- ≤5 页预览 +（可选）模型角色分类；  
- JSON 校验 / 重试 / 规则回退；  
- 产出 proposals + logs + scope 快照。

### Step 4 — 人工核对

表格展示标题/附件 from→to、来源、把握度；用户勾选。

### Step 5 — OK 执行

`proposalToAtomSteps` → `AtomTools.runPlan(steps, rehydratedScope)`；汇总变更与错误。

### Step 6 — 回归验收清单

- [ ] 单选：阅读侧栏仍正常  
- [ ] 多选：侧栏 DeepRead 图标可消失（平台限制，可接受）  
- [ ] 右键 / 工具菜单：能弹出**可见**整理窗口  
- [ ] 未选条目：有明确提示  
- [ ] 模块未加载：有明确提示（非静默）  
- [ ] 生成方案后 OK 前库内标题/附件名不变  
- [ ] OK 后仅勾选项、且仅 scope 内 ID 被改  
- [ ] 故意越权 ID 步骤被拒绝并出现在错误信息中  

### 入口接法

| 入口 | 接流程 |
|------|--------|
| 右键「DeepRead 条目整理…」 | Step 1 → 2 → … → 5 |
| 工具菜单同名项 | 同上 |
| 多选空白区旁路按钮（可选） | 同上 |
| Item Pane 阅读 section | **不接**整理主流程 |

## 5. 痛点清单（已踩坑 / 待解）

按「用户怎么痛 → 根因 → 现状 → 应对」整理，方便审需求时对号入座。

### P0 — 挡主路径（必须先解）

| ID | 痛点 | 用户表现 | 根因 | 现状 | 应对要求 |
|----|------|----------|------|------|----------|
| P0-1 | 多选后阅读侧栏 DeepRead「没了」 | 多选时右侧图标/面板消失，只剩「已选择 N 个条目」 | Zotero 核心：自定义 Item Pane section 只服务单条；`extraItems` 时强制隐藏非 Info section；混合选中走 message 模式 | **平台限制，不能靠 section 救** | 产品接受「多选不靠侧栏」；整理走独立入口 |
| P0-2 | 点「条目整理」菜单像没反应 | 点了右键/工具菜单，没有任何可见 UI | 旧实现把 HTML overlay 贴到 **XUL 主窗口**，浮层经常不可见；失败时还可能静默 | v0.11.6 改为 `openDialog("about:blank")` | 主路径必须是**独立可见窗口**；禁止再依赖主窗口 HTML overlay |
| P0-3 | 整理窗半残缺 + 先报错再留空壳 | Alert 后点确定，仍弹出残缺窗：有标题文案，但「生成方案」等按钮缺失/不可用 | `createElementNS` + `innerHTML` 在 about:blank 下控件常解析不全；绑定 `querySelector` 为 null 抛错时 **root 已 append**，重试又因 root 已存在直接 return → 半残 UI 留在屏幕上 | v0.11.7 改为 `document.write` 整页 HTML，失败时清掉残根 | 整页写入；绑定前校验节点；失败不留半窗 |
| P0-4 | 失败无反馈 / 难排查 | 早期「点菜单完全没反应」；现在有 alert 但仍不知 DOM 里缺了啥 | 入口未 try/catch、模块未加载时静默；渲染错误信息偏技术 | 已有部分 alert | 用户可读错误 + 开发者 log（缺哪个 selector / readyState） |

### P1 — 体验与预期错位

| ID | 痛点 | 用户表现 | 根因 | 现状 | 应对要求 |
|----|------|----------|------|------|----------|
| P1-1 | 「插件多选也应该在侧栏」的预期 | 觉得 DeepRead 坏了 | 官方文档/API 从未承诺多选自定义 section | 需求文档已写明 | 文案/空态说明：多选请用「条目整理」菜单 |
| P1-2 | 多选空白区旁路入口不可靠 | 有时看不到注入卡片 | message / batch-edit-prompt 宿主 DOM 不稳定；MutationObserver 时机 | v0.11.5 注入过，非主路径 | 可选增强；**不能替代**菜单+独立窗 |
| P1-3 | 选中含附件/笔记时「条目数」语义乱 | 显示已选 10 个，但顶层论文可能只有 2 篇 | Zotero 计数含附件/笔记；整理只认顶层 regular item | Agent 已归一顶层 | UI 明确写「N 个顶层条目」 |

### P2 — 能力未完成（非当前堵死）

| ID | 痛点 | 说明 |
|----|------|------|
| P2-1 | 删/挪附件无方案表勾选 UI | 原子与 scope 已有，默认不勾；表里尚未暴露 |
| P2-2 | 写死指令只有一条 | 「仅附件名 / 仅官方标题」等槽位预留未做 |
| P2-3 | 与 Zotero 自带「Edit Multiple Items…」并存易混 | 需文案区分：系统批量改字段 vs DeepRead 官方标题+附件命名 |

### 痛点优先级结论（给开发）

1. **先打通 P0-3**：独立窗能稳定画出可点的整理 UI（生成方案 / OK）。  
2. 守住 **P0-2 / P0-4**：可见窗 + 非静默错误。  
3. **P0-1 不修代码硬扛**，只做产品说明与入口引导。  
4. P1/P2 在主路径通后再排。

## 7. 验收一句话

> 用户多选文献 → 点菜单 → **看得见**整理窗且按钮可用 → 生成带把握度的方案 → 勾选 → OK → 仅改选中范围内的标题/附件名；全程无静默、无越权、无渲染崩溃。
